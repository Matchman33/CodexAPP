# CodexApp — 手机远程控制电脑上的 Codex

在手机上控制电脑里运行的 Codex：**发提示词**、**审批**它想执行的命令/文件改动、实时**看状态**。
**手机端不需要登录 Codex** —— 认证全在电脑侧，手机只跟你自己的中继通信。

```
        ┌─ web/      网页/PWA（任意手机+电脑浏览器，由中继托管）
[ 客户端 ]┤
        └─ mobile/   Expo / React Native（iPhone + Android 同一套代码）
              │
              └──WS(token)──→ [ relay/  Node 中继 ] ──JSON-RPC/stdio──→ [ codex app-server ]
                                本机 4123 端口                          Codex 本体 + 认证 + 执行
```

所有客户端说**同一套协议**连同一个中继 —— 协议定义见 **[PROTOCOL.md](PROTOCOL.md)**（唯一事实来源）。
中继是 `codex app-server` 的唯一客户端，把官方协议（`turn/start` / `turn/steer` /
`turn/interrupt` / 审批请求 / 状态通知）桥接成手机用的简单协议。

## 仓库结构

**CodexAPP 只启动本地中继与端口，不集成或自动启动映射工具。** 默认端口为 4123，原有 Token 鉴权、会话、审批和任务停止保留。公网映射由用户自行选择和维护，**首推 NPS/NPC**；也可以使用 Tailscale、frp 或局域网直连，见下文 [手机远程访问](#4-手机远程访问用户自选映射)。

不想维护服务器时，可使用下文 [Tailscale Serve](#tailscale-serve) 路线，不需要自有服务器、NPS/frp 或本项目云账号。Windows 用户选择 NPS 时可手动执行 `npm run npc:install`，将 NPC 安装到当前项目目录，见 [NPS 快速接入](#nps-快速接入)。此命令只调用用户提供的安装脚本，不自动连接 NPS 或启动系统服务。

已有 frp 用户可自行继续维护其部署；项目不再提供服务器映射安装和续期脚本，具体部署由用户按所选版本官方说明完成。

本地网页构建、服务诊断、打包和业务测试脚本保留。除可选 NPC 文件安装快捷命令外，映射配置、客户端连接、服务端安装、系统服务、自启、证书与防火墙均由用户独立维护；`npm start` 不调用安装脚本。

当前网页/PWA 与 Expo 手机端的「中继直连」支持本地路线；电脑 Node/Electron 云 Agent 启动器仍只启动云模式，不能代替本地中继的 `npm start`。取消映射整合不更改这些启动器或删除已有云配对能力。

```
CodexApp/
├─ relay/        共享后端：Node 中继（spawn app-server + WS + 托管 web + token 鉴权）
├─ web/          网页/PWA 客户端（本地图标与 Markdown，由中继托管）
├─ mobile/       Expo 客户端（iOS + Android 一套代码）            → 见 mobile/README.md
├─ protocol/ts/  从本机 codex 二进制导出的真实协议定义（参考）
├─ archive/      已退役的原生工程（native-android / native-ios，留作参考）
├─ PROTOCOL.md   中继 ↔ 客户端 协议规范
├─ codexapp.config.json   中继配置（首次启动自动生成 token）
├─ install.ps1   Windows NPC 手动安装脚本（不参与 npm start）
└─ package.json
```

```powershell
cd C:\test\CodexAPP
npm install     # 第一次安装依赖
npm start
```

`npm start` 会先运行 `npm run build:web`，将 Lucide 图标、Marked 与 DOMPurify 打包到本地。不依赖第三方 CDN。单独部署云端网页时也需要先构建，并将生成的 `web/vendor/chat-ui.js` 与网页文件一起部署；生成文件不进入 Git。

### Codex 版本路径选择

`codexapp.config.json` 中的 `codexBin` 留空表示自动选择：先使用 PATH 中的独立 CLI，再查找桌面端缓存里的最新可用版本。Windows 桌面端缓存版本须同时存在非空的 `codex.exe` 和 `codex-code-mode-host.exe`；缺少宿主文件、空文件或尚未安装完整的版本会被跳过，候选版本按可执行文件更新时间排序。

旧版曾把桌面端哈希目录下的绝对路径自动写入配置。现在这类路径即使仍有 `codex.exe`，也会重新选择同一桌面端缓存中的最新可用版本，不再固定旧目录。明确配置在桌面端缓存之外的独立 CLI 路径仍优先使用，不要求它具有桌面端专用的宿主文件。需要自动选择时，使用 `"codexBin": ""`。

直连中继与云 Agent 共用该规则。每次启动、异常重连或主动释放后的控制进程重连都会重新解析路径；自动选择结果只用于运行时，不写回配置，也不修改模型、Token 或权限配置。若没有可用的桌面端版本，会提示修复安装或配置独立 CLI，而不是继续启动残缺目录。

首次更新本修复后，需要等待当前任务空闲，再重启实际使用的中继或 Agent。修改配置不会替换已经运行的旧进程。验证命令：`node --test tests/codexBinary.test.mjs tests/codexBinaryStartup.test.mjs`；启动验证使用临时目录和模拟 RPC，不发送真实模型任务。

## Windows 防自动睡眠

Windows 上，中继和电脑 Agent 默认在服务运行期间请求系统保持唤醒，屏幕仍可熄灭，也不需要永久修改系统电源设置。隐藏的 PowerShell 辅助进程使用 `SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED)`，在同一线程持有和释放请求；退出服务后恢复原电源策略。父进程异常退出时，辅助进程通过标准输入 EOF 退出，避免留下常驻防睡眠进程。

此功能在服务等待客户端、Agent 未登录或退出账号但程序仍运行时也有效。要关闭，可在中继 `codexapp.config.json` 或 Agent `agent.config.json` 设置 `"preventSleep": false` 并重启服务；也可设置环境变量 `CODEXAPP_PREVENT_SLEEP=0` 后启动。其他操作系统不启动辅助进程。

中继 `/health` 和 Agent `/api/status` 的 `sleepPrevention` 返回 `{ supported, enabled, active, error }`。只有 Windows API 成功返回后才显示 `active: true`；启动失败或辅助进程异常退出会在日志中告警，不影响远程控制服务运行。辅助进程异常退出后需重启服务恢复防睡眠。

不阻止手动睡眠、合盖触发睡眠或低电量等系统强制行为，不关闭屏幕保护或锁屏策略。此机制不唤醒已睡眠的电脑。已有安装包需要重新构建才能包含此功能。测试：`npm run test:sleep-process`，只启动独立防睡眠测试进程，不操作 Codex 会话。

## 3. 审批与策略

### 权限生效时机

网页保存沙箱和审批策略后，运行中的任务继续使用原权限，不中断，也不会自动批准已有审批。当前任务结束后，后端自动同步同一会话的权限，再执行排队消息；空闲且已接续的会话立即同步，无需重启中继或新建会话。多次修改以最后保存的选择为准。

输入框上方和设置中分别显示当前已确认权限、待生效选择及同步结果，刷新网页后仍能看到状态。只读历史不会因修改设置自动获取写入占用，接续或发送后生效；尚未发送过消息的新会话在首次任务开始时应用选择。同步失败会显示错误并暂停队列，检查原因后再次保存设置重试，成功后手动继续队列。

设置仅控制本项目启动的 Codex 会话，不会授予 Windows 管理员权限，也不能绕过操作系统或上游服务的限制。首次更新代码需重新启动实际使用的中继或 Agent 才能加载此功能；之后修改权限不需要重启。

专项验证：`node --test tests/sessionPermissions.test.mjs tests/approvalSettings.test.mjs` 和 `npm run test:permissions-web`。浏览器测试使用独立随机端口、390 像素宽度与模拟 RPC，不向真实模型发送任务，也不重启正在使用的服务。

### 模型与思考等级

在网页或 Expo 手机端的「设置 → 模型」选择模型，也可切换「自定义模型」填写服务商的模型 ID。列表由电脑端 Codex 动态提供，可刷新；选择「Codex 默认」恢复当前工作目录的 Codex 配置。服务商是否支持某个模型以实际调用结果为准。

点「应用」保存，或点「新建会话」保存并创建会话。模型从下一条消息开始生效，不中断当前任务。模型选择保存在局域网中继的 `codexapp.config.json`，或云 Agent 用户配置目录的 `agent.config.json`，重启后保留；不改 Codex 本身的配置或登录信息。云端使用时需更新电脑 Agent 与托管的网页，Expo 客户端也需加载新版代码。

「思考等级」按所选模型的能力动态提供，包括低、中等、高或服务商提供的扩展等级；不是每个模型都支持所有等级。目录未提供能力信息时可输入自定义等级，最终是否支持以服务商实际结果为准。更换模型时，不兼容的等级会恢复默认。

等级保存为 `reasoningEffort`，与模型一起原子保存；下一次发送通过官方 `turn/start.effort` 传入。选择「Codex 默认」后，读取工作目录的有效默认等级，或使用所选模型的目录默认等级，并显式覆盖已有会话的旧选择。无法确定默认且原会话已有明确等级时，会提示选择明确等级，不悄悄沿用旧值。调整不打断当前任务，也不影响「纠偏」中的已运行任务。

### 网页界面

- 手机使用侧边会话抽屉，桌面使用常驻侧栏；支持搜索项目与对话、显示当前会话、快捷新建。
- 顶部模型入口与输入框旁的思考入口打开设置；网页可选浅色、深色或跟随系统，外观只保存在当前浏览器。
- 用户消息使用气泡，助手消息采用不带外框的阅读布局；支持安全 Markdown、代码块、表格与复制回复。不会加载消息中的远程图片或执行 HTML 脚本。
- 阅读旧消息时，流式回复不自动拉回底部；点击向下箭头回到最新消息。输入框适配移动端可视区域与软键盘。
- 保留任务停止、纠偏、审批、文件差异和会话占用确认。新版 Expo 客户端同步加入思考等级和中性深色聊天界面；原生端仍以可选择文本显示回复，不等同于网页 Markdown 渲染。

### 删除会话与解除占用

网页打开会话直接查看历史，不检查或抢占写入权。发送消息或明确接续时遇到外部占用，才显示持有进程与受影响会话，用户确认后才能结束进程。等待消息保留在原会话队列，接管后需手动继续；不会悄悄丢弃或重复发送。设置中的「解除当前会话占用」只释放本项目自己的订阅，不结束外部进程。

已打开会话栏支持在多个会话之间切换，不中断后台任务；不同会话可以同时执行，各自保留草稿、图片、历史阅读位置、队列、审批和权限设置。不同浏览器的选择互不影响。后端最多缓存 32 个会话上下文，优先淘汰未查看的空闲只读上下文；网页保留最多 8 个历史阅读窗口，草稿仍按会话保存。关闭标签不删除历史，后台运行或有等待消息的会话仍显示状态入口。

只读页面约每 2 秒刷新最新历史页，失败时退避至最多 30 秒，隐藏页面暂停轮询。外部进程的内容在 Codex 只读接口可见后更新，不保证尚未落盘的每个文字增量都能即时同步。向上阅读旧页时保持位置，新内容在返回最新页后可见。

### 交互终端

点击聊天输入框旁的终端图标打开完整终端，默认从当前会话的工作目录启动；尚未打开会话时使用项目配置的默认目录。Windows 使用 PowerShell，Linux/macOS 使用用户 shell。支持连续输入、`cd`、交互提示、ANSI 颜色、窗口缩放和 `Ctrl+C`。手机面板提供 Esc、Tab、方向键、中断、清屏与粘贴按钮。

终端直接运行在项目所在电脑，使用服务进程的系统账户权限，不调用 AI、不进入消息队列，也不受 AI 会话的沙箱与审批选项控制。它仅通过已有 Token 鉴权或云端配对后的连接提供，不增加公开命令执行接口。可在电脑端配置 `terminalEnabled:false` 并重启服务来禁用。

- 收起面板或网页断线不会结束进程；重新连接会恢复有界屏幕状态，不自动重放按键或命令。终端初始目录会显示在面板，之后的 `cd` 只影响该终端。
- 最多同时运行 8 个终端。多页面可以查看同一终端，只有控制页面能输入和缩放；其他页面点击键盘图标明确接管输入。结束终端需点击垃圾桶并确认，正常退出也会显示退出码。
- 存在活动终端时，项目重启会明确拒绝，需先结束终端，避免误中断其中的程序。终端进程不跨服务重启恢复；脱离终端自行运行的后台服务不保证随终端关闭退出。
- 后端保留最多 500 行屏幕滚动记录，单次输入最多 16384 个字符。页面处理输出过慢时暂停该页面同步，命令继续运行，可通过重新连接恢复当前屏幕；不会无限积累原始输出。
- 有历史输出时滚动条保持可见，可拖动滚动条或使用滚轮浏览；点击向下图标回到最新输出。手机默认开启拖动模式，支持单指拖动、双指缩放；桌面可点击手掌图标切换拖动与文字选择。缩放按钮和 Ctrl＋滚轮调整终端字号（9～24px），缩放比例保存在当前浏览器；查看旧记录时新输出不会强制跳到底部。只读查看者可以缩放和拖动较宽的屏幕，不会改变控制页面的 PTY 尺寸。
- 终端宽度可选择「自适应」或固定 80、120、160、240 列。选择比窗口更宽的列数后，底部会显示横向滚动条，可拖动到右侧，支持键盘方向键及 Home/End；宽度偏好保存在浏览器中。只读窗口跟随控制页面的列数，仍可横向滚动查看，不会修改对方的终端尺寸。
- 终端组件、字体样式及依赖均本地托管。安装后运行 `npm run prepare:terminal` 准备 Windows ConPTY 文件；`npm start` 与 `npm run start:agent` 会自动准备。直接用 Node 启动时应先运行准备命令。
- Linux 的 `node-pty` 需要本机构建工具（如 Python 3、make、g++）。若 npm 提示原生模块安装脚本被阻止，审核后运行 `npm install-scripts approve node-pty`，再运行 `npm rebuild node-pty`。依赖不可用时终端显示不可用，聊天继续运行。

终端验证：`node --test tests/terminalManager.test.mjs tests/terminalHub.test.mjs`、`npm run test:terminal-process`、`npm run test:terminal-web` 和 `node tests/terminal-bundle.integration.mjs`。已在 Windows 上验证真实 PowerShell、目录保持、中断、断线恢复、控制权和打包运行文件；浏览器检查 390 与 1280 像素。测试仅操作隔离目录和自建进程，不运行真实模型任务；Linux 和 Electron 安装包尚需目标平台实机验收。

长输出与手势专项：`npm run test:terminal-navigation`，验证常驻滚动条、触摸与鼠标拖动、双指及按钮缩放、旧内容阅读位置与只读窗口尺寸隔离，不执行真实命令。

### 新建范围与重启项目

点击任意新建入口可选择「在当前项目新建」或「临时会话（无项目）」。临时会话使用独立工作目录，不继承上一个项目目录与目录指令；历史与生成文件不会因关闭页面自动删除，列表归入无项目会话。仍适用用户全局配置、沙箱与操作系统权限。

本地中继用 `npm start` 启动；Node 云 Agent 用 `npm run start:agent` 或现有 Windows 启动脚本启动。它们使用受控启动器，设置中的「重启本项目」会等待本应用当前任务结束、暂停后续队列，保存未执行消息后重启服务及专用 Codex 子进程。网页自动重连，恢复的队列需手动继续。可在等待期间取消重启；其他 Codex、NPS/NPC、电脑系统与远程 Broker 不受此入口控制。

首次更新需要正常重启一次以加载新启动器。直接 `node relay/server.mjs` 等未受管启动方式会禁用网页重启；Electron 需要重新构建后使用自身的重启接口。重启超时请检查电脑端启动日志，页面不会把命令受理当成重启成功。

本地中继运行数据位于用户目录 `.codexapp/relay-<项目路径摘要>/`；云 Agent 位于配置目录的 `sessions/`，可用 `CODEXAPP_DATA_DIR` 覆盖。`sessions.json` 保存临时会话归属，`temporary/` 保存独立工作目录，`restart-queue.json` 是受控重启的一次性队列恢复记录。恢复记录可能包含未发送文字和图片，应按私人数据保护。普通崩溃或强制退出仍不保证队列恢复。

专项验证：`node --test tests/sessionHub.test.mjs tests/writerRaces.test.mjs`、`npm run test:sessions-web`、`node tests/serviceRestart.integration.mjs`。使用随机端口、隔离目录和模拟模型接口，不重启现有 4123，也不向真实模型发送任务。

真实 Codex 只读同步验证：`npm run test:watch-rpc`。创建隔离的写入与读取进程，使用本机模拟 Responses 接口生成两轮测试记录，验证另一进程无需接续即可看见新增历史、不会取得写入权；不调用公网模型，不读取或改动用户现有会话。

占用入口专项验证：`node --test tests/writerControl.test.mjs`、`npm run test:writer-web`；Windows 锁识别使用 `npm run test:writer-process`，只创建和处理临时 Codex 测试进程，不触碰已有会话。

网页会话列表每行右侧提供删除按钮。点击后会显示会话名称和永久删除确认，取消不会发送删除请求；确认后通过 Codex 的 `thread/delete` 删除会话及其派生子会话，不是仅从网页隐藏，也不回滚项目文件。删除成功后同步清理相关等待队列、列表和当前聊天页，不自动创建新会话。运行中或状态未知的目标不能删除；旧版 Codex 不支持此接口时明确报错，不自行删除磁盘文件。

在「设置 → 解除当前会话占用」中确认后，中继先暂停该会话的等待队列，再取消自己对会话的订阅。聊天记录、图片草稿和未发送文字保留；后续发送消息或继续队列时才重新接续。正在运行、等待审批或正在启动的任务需要先停止并等到任务结束。

新版 Codex 取消订阅后可能仍处于卸载宽限期。主动解除会检查已加载列表；若会话仍加载且中继控制的所有会话都空闲，则正常关闭并重新连接本中继启动的专用 Codex 子进程，再确认会话已卸载。网页连接和 Node 中继持续运行，不终止桌面端、CLI 等外部进程。其他进程仍持有自己的订阅时，需要在对应进程中释放；本功能只解除当前中继的占用。

切换或新建会话不再取消后台会话的订阅或暂停其队列。关闭无任务、无等待消息且没有其他浏览器查看的标签时可取消订阅；需要立即交接时，可主动点击「解除当前会话占用」。共享控制进程重连前会检查其他会话，不能影响仍在执行的任务。

实现依据：[OpenAI App Server 的删除与取消订阅接口](https://developers.openai.com/codex/app-server)。直连中继与云 Agent 共用生命周期逻辑，Expo 原生端本次没有增加管理按钮。更新后需在任务空闲时重启实际使用的中继或 Agent，再刷新网页。针对本次改动运行 `node --test tests/threadLifecycle.test.mjs` 和 `npm run test:lifecycle-web`；浏览器验证使用随机端口、390 像素视口与隔离模拟会话，不删除真实历史。

### 接收生成的文件

点击聊天中的文件超链接默认打开预览，不直接弹出下载窗口。图片展示图片预览，文本和代码展示文本内容；Excel、PDF 等暂不支持内容预览的格式会显示说明及手动下载入口，不自动读取或下载。附件旁的下载图标和预览窗口的下载按钮仍可明确保存文件。

回复中用行内代码样式标出的文件名（例如 `docs/说明.md`）以及单独显示的 Markdown 本地路径，也会在附件登记后提供可点击的预览入口。普通命令与代码块不转换。文件引用旁和附件卡片提供复制路径按钮，复制原始电脑路径；普通 HTTP/IP 页面会使用浏览器兼容复制方式，复制整条回复也支持该方式。项目外的绝对路径和相对路径也可登记；隐藏、常见凭据或不存在的文件仍不能读取，但路径可以复制，不会把本地路径当成公网网页打开。

文本或代码链接带 `文件:120`、`文件:120:8`、`文件#L120` 或 `文件#L120-L125` 时，预览会滚动到目标附近并高亮目标行或行范围；长行的列号也用于横向定位。同名链接文本中的行号、紧跟文件链接后的 `:行号` 也可识别。同一个文件的不同链接分别定位，不带行号的链接从顶部打开。目标行不存在或超出前 1 MiB 的预览范围时会显示提示，不自动下载完整文件。验证：`npm run test:file-location-web`。

代码预览使用 Lowlight（基于 highlight.js）进行语法着色，依赖和后台 Worker 均在本地托管，不上传源码、不访问 CDN。默认按文件后缀选择语言，也可在「高亮语言」中手动选择或切回纯文本；浅色与深色主题、行号定位、编码切换和自动换行均保留。

| 语言或格式 | 自动高亮的后缀 |
|---|---|
| JavaScript | `.js`、`.mjs` |
| TypeScript | `.ts` |
| Python | `.py` |
| C / C++ | `.c` / `.cpp`、`.h`（头文件默认 C++，可手动切换） |
| JSON | `.json` |
| HTML / SVG 源码 | `.html`、`.svg` |
| CSS | `.css` |
| Markdown 源码 | `.md` |

TXT、CSV 默认显示纯文本，也可手动选择上述语法。HTML、SVG 和 Markdown 始终展示原始源码，不执行或渲染为页面。着色在 Worker 中完成，超过 131072 个字符、语法树过于复杂或处理超时（1.8 秒）时自动保留纯文本；1 MiB 文本预览上限不变。切换或关闭预览会取消旧任务，避免覆盖新文件。专项验证：`npm run test:preview-syntax-web`。

聊天超链接区分网页与本地文件：`http://`、`https://` 地址正常打开，明确的 `IP:端口`、`localhost:端口` 链接会补全 `http://`，不会误改成附件链接。本地源码链接支持 `文件:行号`、`文件:行号:列号`、`#L行号`，以及 Windows 链接中的 `/C:/` 格式。文件可以位于项目外，但仍须已登记并通过文件校验；不可用文件显示原因，不再生成 `当前IP:端口/#codex-file-unavailable` 这样的假地址。只有占位符而缺少原始文件地址的旧链接无法反推出目标文件。

链接专项验证：`node --test tests/linkTargets.test.mjs` 和 `npm run test:links-web`。示例公网 IP 的请求全部由隔离浏览器本地拦截，不访问真实公网服务。前端更新刷新即生效；后端文件路径识别更新需重新启动实际使用的中继或 Agent。

文本预览窗口提供「自动换行」复选框，每次打开默认关闭。关闭时保留原始行结构，长行可横向滚动；开启后按窗口宽度换行，仅影响显示，不修改文件内容。

展开「文件变更」后，框内的已登记附件保留下载按钮；支持的图片、文本及代码类型同时提供眼睛图标预览，Excel 等其他类型只提供下载。展开框只展示元信息，不会自动读取或传输文件内容。专项验证：`npm run test:file-changes-web`。

AI 生成图片、Excel、Word、PDF、压缩包等文件并在回复中引用路径后，网页聊天会显示附件条目，包含文件名、大小和下载按钮。文件可在项目内或电脑其他目录；PNG、JPEG、WebP、GIF 可点击眼睛图标预览原图；TXT、Markdown、JSON、CSV、HTML、SVG 和常见代码文件也可以点击眼睛图标查看纯文本。Excel、Word、PDF 等文件下载后用相应软件打开，本次不提供表格在线编辑。

- 识别助手回复中的 Markdown 文件链接、行内代码文件路径，以及 Codex 的文件变更和图片生成结果。用命令生成文件时，让 AI 在最终回复提供文件链接即可，例如 §[下载报表](exports/report.xlsx)§。只在命令日志里提及、未明确输出引用的文件不会自动展示。
- 单文件上限 32 MiB，传输按 192 KiB 分块。文件通过原有已鉴权的 WebSocket 传输；云端配对沿用 E2E 加密，无需新增公网文件目录、网盘或代理路由。直连的链路仍需使用 HTTPS 或可信网络。
- NPS 转发下，手机继续使用原 NPS 访问地址，附件沿同一条聊天连接传输，不访问电脑的 `127.0.0.1` 或磁盘路径。聊天中的 Windows 绝对路径会映射为附件操作；文字文件链接下载，图片引用和眼睛按钮预览。下载进度、取消和错误反馈位于聊天附件条目内，完成后不保留独立的已接收或保存状态栏。需要再次保存时，点击聊天记录中的同一下载入口即可。
- 文本弹窗支持选择编码，自动识别 UTF-8、带 BOM 的 UTF-16，并在 UTF-8 无法解码时尝试 GB18030/GBK。所有内容按纯文本展示，不执行 HTML、SVG 或脚本。大文件只接收足够预览前 1 MiB 的分块并明确标注截断，弹窗下载按钮仍可获取完整文件；错误编码或非文本内容会提示改选编码或下载。
- 仅允许当前会话已登记、实际存在且属于允许类型的本机文件。项目外路径（含 `../` 和绝对路径）可以预览，但隐藏目录、常见凭据文件、私钥、网络路径及未开放类型不会成为可下载附件；不会接受客户端直接传入任意磁盘路径。跨项目引用扩大了可通过已登录网页取得的文件范围，请勿在助手回复中放入敏感文件链接。
- 下载期间可以取消；断网、超时或文件被修改会终止接收，不保存残缺文件。文件发生变化、登记信息过期或服务重启后，可重新打开会话获得新的附件信息。刷新和历史分页只传文件元信息，不自动传输原文件。
- 附件对应电脑上当前存在的文件，不保存历史副本；文件被覆盖或删除后，不能从旧聊天恢复原来的文件版本。需要保留多个版本时，让 AI 使用不同的输出文件名。
- 文件读取不进入任务控制队列，下载不应阻塞审批或停止任务。当前能力覆盖网页直连和云端配对，Expo 原生端本次未新增附件界面。

更新后，等待任务空闲再重启中继或云 Agent 并刷新网页。专项验证为 §node --test tests/fileAttachments.test.mjs§ 与 §npm run test:files-web§；浏览器使用单个 390 像素视口及隔离模拟服务，不向真实模型发送任务。

### 上传图片

网页输入框中的图片按钮支持选取照片；电脑端也可以粘贴截图或拖拽图片到输入框。发送前可预览、移除图片，既可发送图文，也可只发送图片。支持 PNG、JPEG、WebP；暂不支持 SVG、GIF、HEIC 和普通文件。

- 每条消息最多 4 张图片。原始单文件最多 20 MiB、总像素最多 3200 万；超过 1 MiB 的图片会缩小并转换为 JPEG，可能损失细节或透明背景，发送前可预览。发送到 Codex 的单图不超过 1 MiB，图片总计不超过 4 MiB。
- 普通图片消息沿用原消息队列，收到受理确认后才清空对应图片和文字；运行中可以继续排队，也可以勾选纠偏。刷新页面不重复提交，已受理的等待图片仍由电脑端队列保存；受控重启可恢复暂停队列，普通退出或崩溃不保证恢复，刷新前未受理的本地草稿不保证保留。
- 图片直接传给电脑端 Codex，不上传第三方图床。云端配对使用原 E2E 通道；中继直连的图片与 Token 仍需用 HTTPS 或可信局域网保护。所选模型和上游服务必须支持图片输入，否则以实际返回错误为准。
- 聊天和历史只传缩略图，避免加载整张 Base64 原图。经本功能发送的缩略图缓存于电脑端 `CODEX_HOME/codexapp-image-previews/`（默认 `~/.codex/codexapp-image-previews/`），用于刷新和历史分页恢复；缓存含图片内容，应按私有数据管理。清理缓存后，原图仍由 Codex 的历史管理，但网页只能显示附件占位。非本功能上传的旧附件不会自动读取电脑文件或下载远程图片。
- 图片能力由后端快照声明。更新后应在当前任务完成后重启实际使用的中继或云 Agent，再刷新网页；云端还需更新 Broker 和托管网页。旧后端会禁用图片按钮；Expo 原生端暂未新增选图控件，文字发送不受影响。

专项验证：`node --test tests/imageInput.test.mjs tests/imagesRelay.test.mjs` 和 `npm run test:images-web`。直连验证使用临时目录、随机端口和模拟 RPC；浏览器只检查一个 390 像素手机视口，不向真实 Codex 发送任务，不重启正在使用的服务。

### 消息排队

新版网页的普通发送由本地中继或云 Agent 管理队列。任务运行中仍可输入并点击发送，此时按钮表示“加入队列”；输入内容收到后端受理确认才清空。等待消息显示在输入框上方，可以取消、折叠列表、暂停或继续队列；真正开始执行时才显示聊天气泡，不会把排队消息提前重复显示为已发送消息。“纠偏”仍直接补充当前任务，不进入队列。

- 同一会话按先入先出执行，只有上一任务明确成功完成才自动开始下一条。停止任务、任务失败、会话被占用或 Codex 连接中断时暂停等待队列，检查状态后手动继续。
- 消息绑定原会话。切换会话不暂停后台队列，不会把等待消息发到另一个会话。
- 关闭或刷新网页不清空队列；网页发起的受控重启保存等待消息和受理凭据，恢复后暂停。普通退出或崩溃不保证恢复。多网页共享后端任务，各自选择查看的会话。
- 全部会话合计最多保留 20 条等待消息，单条最多 65536 字符，总计最多 262144 字符。模型、思考等级和审批策略按消息实际开始执行时的当前设置生效。
- 确认超时不自动重发，网页保留输入内容并提供重试确认按钮。重试沿用同一请求 ID，每个会话保留最近 200 个受理凭据并保护待执行消息，受控重启也恢复凭据；超出此窗口或普通崩溃后不能保证幂等，请先核对队列和历史。

需要同步更新网页及实际使用的中继/Agent。旧服务端不支持队列时，网页保留原发送行为，运行中只能纠偏；现有 Expo 客户端未添加队列界面。

队列回归测试：运行 npm run test:queue-web，使用独立随机端口、模拟 Codex RPC 和隔离浏览器验证受理确认、FIFO、重复请求、取消及停止后继续，不向真实模型发送消息。截图保存在被 Git 忽略的 dist-check/queue-ui/。

### 实时输出与工具状态

助手文本通过 WebSocket 推送，网页按浏览器帧合并更新，只修改正在变化的消息，保留其他可视消息节点。工具从开始到完成更新同一条记录：可展开查看命令与日志、退出码、文件列表及 diff，失败和停止不会显示为成功。命令日志滚到末尾时跟随新输出，向上阅读时不强制拉回底部。

分页模式中，超长实时消息保留开头和最新各最多 8192 字符，默认展示最新窗口并显示内容位置，可点击箭头“查看开头”或“查看最新”。完成后仍通过原历史接口分段读取完整内容，不无限累积全文；截断片段以纯文本显示，完整助手回复仍支持安全 Markdown。重新接续时如果只拿到了历史开头，新输出按真实位置显示，不拼接缺失的中间内容。

协议需要网页和实际使用的中继或 Agent 同步更新。旧后端未携带条目 ID 的命令输出不会随意归入当前任务，工具完成后仍可看到结果。网页未收到数据时，优化渲染不能消除模型生成或公网线路延迟。

定向验证：npm run test:stream-web。默认只测试 390 像素手机宽度，使用独立端口、模拟 Codex 通知及真实历史分段代码，不发送真实模型任务；测试帧合并、工具状态、最新窗口、内容导航和阅读位置。可通过 CODEXAPP_TEST_WIDTH 指定本次需要的宽度，截图在 dist-check/stream-ui/。

### 长会话加载

新版网页打开会话时只读取最近一页，向上滚动或点击向上箭头加载更早记录；已移出缓存的较新记录可通过向下箭头或回到最新消息重新读取。历史仍完整保存在 Codex 中，显示分页不会缩短模型上下文，也不影响审批、停止、纠偏和会话占用处理。

每页最多 50 条、65536 个文本字符，长消息与工具输出按 8192 字符分段查看，内容范围标记显示当前段与完整长度。网页保留 3 页历史和最多 100 条近期更新，只为可视区域附近最多 60 条消息创建 DOM；不会因持续翻页无限堆积全文。流式阶段用安全纯文本更新，完成后再渲染 Markdown，避免反复解析长回复；长消息的复制按钮仅复制当前段。

本地中继和云 Agent 共享分页实现，服务端在分页模式保留最多 100 条近期事件。现有 Expo 客户端未启用新分页协议，保留原完整历史读取兼容路径，不声明分页的旧客户端不享受此后端缓存上限。旧服务端与新网页混用时也不能保证传输大小有界，应同步更新网页及实际使用的中继/Agent。

Codex 二进制版本的支持程度不同：优先使用条目分页；尚未实现时降级为一次读取一轮，而不是整个会话。单轮特别大时仍可能有后端读取延迟，Codex 自身读盘与巨大任务差异也不在本次网页优化的保证范围内。协议与字段见 [PROTOCOL.md](PROTOCOL.md)。代码更新后需重启实际使用的中继/Agent 并刷新网页。

回归测试：`npm test`、`npm run test:web`、`npm run test:history-web`。长历史测试使用 2000 条模拟消息、独立随机端口及隔离 WebSocket，检查三种屏幕宽度的分页、缓存淘汰、内容分段、迟到响应和流式归并，不操作真实 Codex 会话。截图输出到被 Git 忽略的 `dist-check/history-ui/`。

### 审批策略

要让手机收到审批，中继会在每个会话强制审批策略（你的 `config.toml` 是 `never`，不强制就没审批）。
App 里可调：`on-request`(默认) / `untrusted`(几乎每条都问) / `on-failure` / `never`；
配合沙箱 `workspace-write` / `read-only` / `danger-full-access`。

> `permission` 类审批 v1 只支持拒绝；命令、文件改动审批的批准/拒绝都完整。

审批策略与沙箱选择点击“应用”后保存到当前中继或 Agent 的配置文件，重启后保留。`never` 从下一条实际开始执行的任务生效，包括队列中的等待消息；已经运行的任务和已出现的审批请求不会被追溯修改或自动批准。沙箱选择仍在新建或接续会话时应用。`never` 不等于 `danger-full-access`：不会自动扩大读写或网络权限，沙箱阻止的操作可能直接失败。

日常验证按改动范围运行，例如本次审批修复使用 `node --test tests/approvalSettings.test.mjs`；共享设置模块变更时，只补测直接受影响的保存与兼容用例，可用 `--test-name-pattern` 过滤。不默认重复跑无关旧用例或全量浏览器测试，完整回归留到发布验收或明确需要时执行。

## 4. 手机远程访问（用户自选映射）

公网 IP 映射首推用户独立部署 NPS/NPC。下文同时保留无需自有服务器的 Tailscale Serve 操作，已有 frp 用户也可自行维护原部署。三者均不参与 npm start，不启用任何映射工具也能使用本地中继。实际速度以同网络对比结果为准。

### 方案选择

| 方案 | 使用方式 | 自有公网服务器 |
|---|---|---|
| NPS/NPC（首推） | 服务器运行 NPS，项目电脑运行 NPC，按电脑分配独立 TCP 映射 | 通常需要 |
| Tailscale Serve | 手机与电脑接入同一 tailnet，使用私网 HTTPS 入口 | 不需要 |
| frp | 用户按所选版本官方说明独立维护隧道 | 通常需要 |
| 局域网直连 | 使用电脑局域网地址、本地端口和应用 Token | 不需要 |

### NPS 快速接入

Windows 项目根目录可手动执行客户端安装：

```powershell
npm run npc:install
```

等价命令为 `powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 npc latest .`。最后的 `.` 是当前项目目录，输出为根目录 `npc.exe` 和 `conf/npc.conf`。必须使用 `npc` 模式：`nps` 安装服务端，`all` 安装两者，服务端包可能覆盖本项目 `web/`，不要在本目录使用这两个模式。

此快捷命令仅适用于 Windows，不会自动连接 NPS、注册服务、开机自启或启动另一个 Codex。`latest` 在安装时尝试解析最新发行，并使用脚本原有镜像回退；不保证与既有服务器兼容。需对齐版本时，例如执行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 npc v0.34.7 .`。安装脚本未提供包 SHA-256 校验，请用户自行确认下载来源，不在 NPC 正使用二进制时重跑安装。

安装后编辑 `conf/npc.conf`，按服务器实际设置填写 `server_addr`、`conn_type` 和 `vkey`。已有配置会保留，新模板写入 `conf/npc.conf.default`。不要用发行包示例密钥，不把真实 vkey 放入 package.json、公开命令、日志或截图；相关客户端配置和二进制均被 Git 忽略。

先确认项目电脑的中继已运行，健康检查的 `ok` 和 `codexConnected` 都为 true，再手动启动 NPC：

```powershell
Invoke-RestMethod http://127.0.0.1:4123/health
.\npc.exe -config=".\conf\npc.conf" -log=off
```

如果本机中继已运行，不要重复 npm start。NPC 应与 CodexAPP 在同一电脑、同一本地网络环境运行，不能把服务器、WSL 或容器里的回环地址误当成 Windows 本机服务。不要同时运行相同设备身份的多个 NPC。

NPS 服务器由用户独立安装和管理，不在服务器安装 CodexAPP 或复制电脑 Codex 凭据。建议 NPC 使用 TLS 接入服务器（当前配置示例为 TCP 8025），面板创建 TCP 隧道；HTTP 和 WebSocket 都可由同一 TCP 映射承载，客户端 `-type=ws` 不是网页使用 WebSocket 的必要条件。

| 隧道字段 | 建议 |
|---|---|
| 类型 | TCP |
| 客户端 | 运行 CodexAPP 的对应电脑 |
| 服务端端口 | 用户指定且空闲，例如 18123；按需放行安全组和防火墙 |
| 目标 | 127.0.0.1:4123，由项目电脑的 NPC 访问 |
| 本地代理 | 关闭，避免由服务器直接访问回环目标 |
| PROXY protocol | 禁用 / 0，本地 Node HTTP 服务不解析 V1/V2 前缀 |

两台电脑可以各自使用本地 4123，但应使用独立 vkey 和公网端口，例如 A 为 18123、B 为 18124；访问哪台电脑就填写那台的 CodexAPP 应用 Token。NPS vkey、面板密码和应用 Token 不能互换。

浏览器入口示例为 `http://服务器IP:18123/`。NPC 到服务器的 TLS 不会让公网浏览器入口自动变成 HTTPS；公网 HTTP/WS 仅用于临时联通测试，正式任务和审批应使用 HTTPS/WSS 或可信私网入口。NPS 面板、证书、来源限制及后台运行仍由用户维护。

### Tailscale Serve

已有 **Tailscale Serve** 方案不使用 Funnel 公网入口。电脑与手机都安装并连接同一个 Tailscale 网络，Serve 为本地中继提供仅限私网访问的 HTTPS 地址，不需要部署本项目的云端 Broker。

Serve 在两端成功点对点直连时有机会减少中转延迟；无法直连时仍可能走中继，不能保证一定比 Funnel 快。手机必须开启 Tailscale，仅用普通浏览器但未接入 Tailscale 网络无法访问。

#### 电脑端启动

1. 在项目根目录运行 `npm start`，保持中继进程运行。确认本机访问 `http://127.0.0.1:4123/health` 返回 `"ok": true`。
2. 在另一个 PowerShell 窗口启用 Serve：

   ```powershell
   tailscale serve --bg 4123
   ```

   首次使用如果提示 Serve 未启用，打开命令输出的授权链接，完成 HTTPS 等授权；若没有自动继续，再运行一次上述命令。
3. 成功输出应包含 **`Available within your tailnet`**，例如：

   ```text
   Available within your tailnet:
   https://my-pc.tail123456.ts.net/
   |-- proxy http://127.0.0.1:4123
   ```

   使用命令实际输出的完整域名，示例域名不可直接使用。`--bg` 让代理在后台运行，可以关闭该命令窗口；运行 `npm start` 的中继进程和电脑上的 Tailscale 仍需保持运行。

如果此前启用了 Funnel，先关闭公网入口，再启用 Serve：

```powershell
tailscale funnel --https=443 off
tailscale serve --bg 4123
```

确认 `tailscale serve status` 显示 **`tailnet only`**。本项目不需要 Funnel，不应再运行 `tailscale funnel --bg 4123` 将同一地址改回公网模式。

#### 手机连接

1. 手机安装 Tailscale，登录并加入电脑所在的同一网络，开启连接。确认电脑和手机都在线；手机无需与电脑连接同一 WiFi。
2. 浏览器打开 Serve 输出的 HTTPS 地址，**不要加 `:4123`**。网页识别到电脑中继后，默认显示 **「中继直连」** 并填入当前页面地址，不需要注册云账号。
3. 确认中继地址是同一个完整 HTTPS 地址，Token 填电脑端 `npm start` 输出的 Token，再点连接。不要填旧的 `http://192.168.x.x:4123` 或 `http://100.x.x.x:4123` 地址；WebSocket 会自动使用 `wss://`。已有自定义地址不会自动替换，可以点击「使用当前页面地址」后重新连接。

Expo 客户端也使用相同的 HTTPS 中继地址和 Token。浏览器支持时可添加到主屏幕；HTTPS 本身不保证手机锁屏后网页仍保持连接或持续接收通知。

#### 首次连接与切换网络

- 在家和外出均使用同一个 Serve HTTPS 域名。局域网 IP 与 HTTPS 域名是不同的网页来源，各自保存连接配置；换地址后需要重新输入 Token，不会共享登录信息。
- 已保存配置时会先进入对话页，但只有收到中继的初始化消息后才允许发送。看到对话页不代表连接已经成功。
- 网页的登录请求与连接初始化有 12 秒超时处理，失败后单次退避重试；网络恢复、从后台回到前台时立即重建连接。右上角重连按钮可手动重试，不会自动重新发送提示词。
- HTTPS 页面填写 HTTP 中继地址会直接提示更换地址，而不是一直显示连接中。Token 无效时保留地址并返回连接页，避免反复自动重连。
- 这些处理减少页面等待和旧连接干扰，不能消除 Tailscale 建链或中继线路的延迟。手机切到移动网络时仍需保持 Tailscale 开启。

#### 检查与关闭

```powershell
tailscale serve status              # 应显示 tailnet only
tailscale serve --https=443 off      # 关闭 HTTPS 私网入口，本地中继继续运行
tailscale status                    # 检查电脑和手机是否在线
```

- **手机打不开域名**：先确认手机 Tailscale 已连接同一网络、电脑在线，并检查私网访问规则及 MagicDNS。Serve 不是公网访问，不需要等待 Funnel 公网 DNS 生效。
- **区分域名故障与应用连接故障**：在手机打开 `https://<实际域名>/health`。返回包含 `"ok": true` 的 JSON 表示 HTTPS 转发已通；若网页能打开但应用断线，检查「中继直连」模式中的中继地址是否已换成该 HTTPS 域名，以及 Token 是否正确。
- **电脑能打开、手机打不开**：检查手机是否仍开启 Tailscale、是否在同一网络、访问规则是否允许；手机切换移动网络后也需保持 Tailscale 连接。
- **本机 `/health` 也打不开**：检查中继是否仍运行、端口是否为 4123。中继端口改变时，Serve 的目标端口也需同步修改。

访问范围和 HTTPS 配置见 [Tailscale Serve 官方文档](https://tailscale.com/docs/features/tailscale-serve)。

### 延迟与排错

优先检查电脑与手机之间的连接类型。电脑上运行 `tailscale ping <手机的 Tailscale IP>`，观察是否建立直连；`tailscale status` 也可查看活动连接的 direct/relay 信息。直连不代表一定快，仍需比较实际请求耗时。NPS 或 frp 入口则分别检查服务器监听、客户端在线状态、目标服务与实际 HTTP/WebSocket 请求。

模型响应等待与手机到电脑的网络等待是两段不同的链路。换公网入口不能直接解决模型服务商慢的问题；提高思考等级也不是网络加速方式。

## 5. 安全

- **Token 即权限**：拿到地址+Token 就能批准你电脑上的命令，当密码保管。
- 任何映射都不替代项目 Token 校验，不在分享链接、截图或公开日志中附带 Token。选择 Serve 时保持私网范围，不把同一入口误改为 Funnel 公网；选择 NPS/frp 时，由用户维护 HTTPS/WSS 和来源限制，不直接把本机 4123 裸露到公网。
- `~/.codex/config.toml` 内含第三方中转明文 token，别外发该文件/截图。
- 审批策略别设 `never`，否则远程控制等于放开。

## 会话占用与停止

遇到 `already has an active writer` 表示同一会话已有其他 Codex 进程持有写入锁，空闲会话也可能仍被占用。网页与手机端会显示「会话被占用」，可重试接续、重新检查占用，或在 Windows 上确认「结束进程并尝试接续」。

结束前会列出 PID 和所有受影响会话，并要求二次确认；不会自动强杀，不会批量结束其他 Codex，也不会删除锁文件。多个占用者、无权限或无法可靠识别时不提供结束操作。进程身份或受影响会话在确认后变化，操作会被拒绝，需重新检查。

**结束的是整个占用 Codex 进程，可能同时影响多个会话。已产生改动不会回滚，已启动子进程可能继续运行。优先在原电脑客户端正常停止或关闭会话。** 当前会话的「停止」按钮也已补齐 `turnId` 参数，接续本中继的运行中会话会保留任务状态。

自动测试：`npm test`。Windows 隔离进程测试：`npm run test:writer-process`（临时配置目录、独立进程、不发送模型提示词，不操作现有会话）。
