# 消息排队设计与实施计划

用户已确认：后端按会话 FIFO 排队，成功完成后自动执行下一条；停止或失败时暂停，支持取消和继续。网页关闭不丢队列，服务重启清空。

## 实现约束

- 本地中继与云 Agent 复用 `PromptQueue`，实际启动仍通过已有任务控制队列串行执行。
- 队列绑定会话，不自动切换到其他会话执行；离开会话时暂停旧队列。
- 最多等待 20 条，单条最多 65536 字符，总等待文本最多 262144 字符。
- 请求 ID 提供有限窗口去重；网页收到受理回执才清空对应草稿，不自动重发未确认的任务。
- 上一任务明确成功才推进；中断、失败、占用及后端断开均暂停，重复和过期完成通知不启动额外任务。
- 模型及审批采用实际执行时的当前配置；队列不会改变沙箱和审批能力。
- 排队消息只显示在待执行列表，开始执行时才产生聊天消息回显，沿用同 ID 更新及历史身份合并。

## 实施与验证

1. 测试并实现共享 FIFO、受理去重、取消、暂停、继续及启动／完成竞争处理。
2. 接入直连和云端，测试连续执行、停止、失败、占用、切换会话和重复通知。
3. 网页接入受理回执、队列列表及图标控制，兼容不支持队列的旧服务。
4. 用隔离浏览器验证三种宽度、弱网回执、队列操作和已有聊天能力；更新中文说明。
