## 目标与推荐行为

### 多个会话同时打开

- 前端提供已打开会话栏，能够在运行中的会话、其他项目会话及临时会话间切换。
- 切换只改变浏览位置，不停止任务、不解除后台会话订阅、不暂停它的正常等待队列。不同会话可以并行执行；同一会话仍按原队列顺序执行。
- 草稿、所选图片、滚动位置、历史窗口、待确认发送、任务状态、权限待生效状态、审批及队列按会话隔离。
- 后台会话显示运行中、待审批或有新消息的标记。停止与审批命令携带目标会话及任务标识，不依赖屏幕上最后一次选中的会话。
- 关闭标签不等于删除会话或停止任务；存在后台任务时仍保留可返回的状态入口。会话永久删除沿用原确认流程。
- 各浏览器维护自己的选中标签，避免一台手机切换会话使另一台设备的页面跳转。后端任务和队列仍由同一实例共享。
- 历史继续分页，限制每个会话缓存；非当前空闲会话优先释放正文缓存，保留草稿和状态，重新打开时分页恢复，防止多会话导致内存无界增长。

### 发送时检查占用，允许旁观

- 打开会话只读取历史，不调用写入接续、不弹占用对话框。
- 用户发送消息后，后端先尝试取得该会话写入权；发生占用冲突才展示占用处理。发送意图与请求 ID 保留，不自动重复提交，也不在旁观期间发送到其他会话。
- 被其他进程占用仍可以阅读历史。只读更新不自动取得写入权，也不结束外部进程。
- 本应用持有的会话继续通过通知推送。外部持有的会话优先使用可验证的只读更新接口；没有外部通知能力时定向刷新当前可见会话的最新历史页，初始间隔约 2 秒，错误时退避、隐藏页面时暂停或降频。
- 外部更新的实时程度取决于 Codex 将内容暴露给只读接口的时机；不承诺另一进程尚未落盘或未公开的每个文字增量都能即时看到。
- 新页通过稳定条目 ID 合并，保持阅读位置与已加载旧页，显示最新同步时间和失败状态，不整页闪烁或反复加载完整历史。

### 修复解除外部占用

- 先用隔离测试复现：原进程自行退出、结束后锁释放滞后、外部程序重新生成持有者、确认超时、进程身份变化、检查超时与权限不足。
- 保留 PID、启动时间、可执行文件和受影响会话核对；保留现有结束进程的二次确认，不删除锁文件，不按进程名批量结束。
- 若已确认的原进程自行退出且目标无新持有者，将其视为占用已经解除，继续尝试接续。
- 原进程退出后有限重试检查释放和接续；出现新持有者时停止接管，刷新冲突信息并重新确认，不自动结束新进程。
- 区分“进程未退出”“进程已退出但接续失败”“出现新的持有者”，前端不把所有阶段统一显示为解除失败。
- 多会话下解除本应用单个会话的占用不能重启其他正在工作的控制连接。复用现有生命周期逻辑时，需要移除依赖全局当前会话的判断。

### 临时会话与项目会话

- 所有新建入口使用同一选择菜单，明确列出“在当前项目新建”和“新建临时会话（无项目）”；当前没有项目时不提供含糊的继承选项。
- 项目会话显示将使用的目录；沿用当前项目环境和适用的项目指令。
- 临时会话使用应用数据目录下每个会话独立的工作目录，不能通过省略 `cwd` 意外回落到上一个项目或 CodexAPP 源码目录。
- 临时会话的无项目归属在本应用元数据中持久化，重启后仍显示在无项目分组；不直接覆盖 Codex 桌面应用的私有全局配置。
- “临时”表示没有关联项目，不表示关闭页面就删除历史或文件。历史仍由 Codex 保存，生成文件位于该会话自己的工作目录并沿用附件读取限制。
- 临时会话不加载上一个项目的目录指令，但仍受用户全局配置、沙箱策略及操作系统权限约束。

### 前端重启本项目

- 设置菜单增加重启图标入口，显示重启目标为当前连接的本地中继或云 Agent；重启应用服务及其专用 Codex 子进程，不重启电脑、NPS/NPC、远程 Broker 或外部 Codex。
- 重启命令沿用已有认证通道，并包含一次性确认与幂等请求标识，不增加匿名执行命令接口。
- 默认行为为等待本应用所有当前任务结束后重启。等待期间不再启动队列的新任务；用户可以取消计划重启。外部进程运行的任务不属于等待范围，也不能被本入口结束。
- 尚未执行的已受理消息写入受限的恢复记录，重启后恢复为暂停状态，保留原会话与请求 ID，由用户手动继续。恢复记录保存失败时取消重启并明确报错，避免悄悄丢失队列。
- 仅恢复确认尚未发送的等待消息；发送结果不确定的消息单独提示核对，禁止自动重放。
- 使用固定启动入口和参数的受控启动器处理退出、重新监听与启动失败。页面保留草稿和打开标签，断线后自动重连，健康就绪后重新获取状态和历史游标。
- Node 本地中继与 Node 云 Agent 复用启动机制，Electron 使用应用自身重启接口。由外部服务管理器托管的启动方式必须有明确重启适配，未支持时不虚假报告可重启。
- 开发验证使用独立端口和测试进程，不操作用户现有 4123 服务。首次部署新增启动器仍需用户正常重启一次，之后可使用网页入口。

## 实现方案比较

1. 推荐：一个应用级管理器按会话 ID 保存上下文，共享 Codex RPC 连接及事件分发。浏览选择按客户端保存，执行状态按会话保存，减少后台进程数量，同时支持并行会话与统一重启检查。
2. 每个已打开会话启动独立 Codex 控制进程：隔离更直接，但进程、内存和恢复成本较高，也会扩大占用排查复杂度。
3. 只做前端标签、保留单会话后端：改动最小，但无法满足后台继续执行和并行会话要求，不采用。

本地中继和云 Agent 共用新增的会话管理与生命周期模块，传输层分别保留直连认证、云配对和附件传输。旧客户端未声明多会话能力时保留单会话协议适配。
