# 网页交互终端

用户已选择完整交互终端，按此方案实施，不提交 Git。

- 前端独立终端面板，采用本地托管的 xterm.js；服务端使用 node-pty，Windows 使用 PowerShell，Linux/macOS 使用登录用户的 shell。支持交互输入、目录切换、实时 ANSI 输出、缩放、粘贴和 Ctrl+C。
- 从当前会话目录启动，无会话时使用已配置的默认目录。终端独立于 Codex 任务和会话写入占用，不调用模型、不改变 AI 审批策略；显式显示系统账户权限。
- 复用已鉴权的直连 WebSocket 或已配对的 E2E 通道，不创建匿名命令执行接口。终端 ID 由后端生成，输入与窗口尺寸校验；不会把命令字符串拼接进启动器参数。
- 同一服务最多 8 个活动终端，支持列表、创建、重新连接、清屏与明确结束。关闭面板或连接断开不结束进程；应用重启不恢复 shell 进程、不自动重放输入。
- 多页面可查看同一终端，但只有控制页面能输入或改变大小；其他页面可明确接管控制。关闭终端需要确认，避免把关闭面板误当作结束程序。
- 后端用有界的终端屏幕状态恢复断线页面，不保存无限原始输出。输出使用序号与渲染确认，处理慢的页面暂停同步并允许手动恢复；后台命令继续运行。
- 存在活动终端时阻止安排项目重启；明确结束所有终端后再按原流程等待 AI 任务完成并重启。等待重启期间不允许创建新终端。
- Native 依赖缺失或平台不支持时，终端报告不可用，聊天与已有功能继续运行。Node/Electron 分发构建携带相应平台的 node-pty 运行文件。
- 只验证新增终端、身份/控制权校验、重连恢复、输出背压、项目重启直接调用方、一个手机和一个桌面视口；真实 PTY 测试使用隔离目录与自身子进程，保留用户的 4123 服务。
