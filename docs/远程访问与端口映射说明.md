# 远程访问与端口映射说明

## 1. 项目边界

CodexAPP 的 npm start 只启动电脑本机的 HTTP/WebSocket 中继和 Codex app-server，默认监听 4123，不自动检测、安装或连接映射工具。映射方案由用户选择，不管理其面板、密钥、自启、系统服务、证书、防火墙和云安全组。Windows 用户可以单独执行可选的 npm run npc:install，调用用户提供的 install.ps1 仅安装客户端文件，见 [NPC 客户端安装说明](NPC客户端安装说明.md)。

“本地服务”是指运行在自己的电脑，并非只允许回环访问。默认 host=0.0.0.0，支持局域网直连；只需要同机映射时可以改为 127.0.0.1。原有应用 Token、聊天、审批、会话历史、任务停止、占用处理和云端配对均保留；本地启动不要求云账号。

## 2. 启动和端口设置

在项目根目录运行：

~~~powershell
npm install
npm start
~~~

已有中继运行时不要重复启动，不为接入映射而重启它。npm start 先构建本地网页依赖，再运行 relay/server.mjs；不会自动开放公网入口。

在 codexapp.config.json 中调整 host、port，例：

~~~json
{
  "host": "127.0.0.1",
  "port": 4123
}
~~~

这是字段示例，不要用它覆盖整个配置文件，否则会丢失 token 等现有设置。HOST、PORT 环境变量可覆盖对应值；更改仅在下一次由用户启动中继时生效。需要局域网直接访问时保留 0.0.0.0，并按需配置电脑防火墙。

确认本机服务健康：

~~~powershell
Invoke-RestMethod http://127.0.0.1:4123/health
~~~

ok 和 codexConnected 都应为 true。它仅说明本机中继和 Codex 已就绪，不代表公网、WebSocket 或真实任务流程已验收。不要使用 npm run probe 检查网络入口：该命令是 Codex 协议探测，会另启 app-server。

## 3. 用户选择映射方案

| 方案 | 使用场景 | 是否需要自有公网服务器 |
|---|---|---|
| NPS/NPC（首推） | 希望使用 Web 管理面板、独立公网端口与多电脑映射 | 通常需要 |
| Tailscale Serve | 不想维护服务器，访问设备可加入同一 tailnet | 不需要 |
| frp | 已有 frp 部署或偏好手工配置隧道 | 通常需要 |
| 局域网直接访问 | 手机和电脑在可互通的本地网络 | 不需要 |

首推 NPS 是文档建议，不是项目依赖。用户可以替换映射工具，不修改 CodexAPP 的业务代码；实际速度取决于网络路径与服务器位置，不能保证 NPS 一定比 Tailscale 快。

所有工具需要保留 HTTP 路径、查询参数和 WebSocket 升级；映射停止仅使其入口不可达，本地中继应继续运行。

## 4. NPS 独立接入示例

~~~text
浏览器 -> 服务器IP:18123 -> 用户独立部署的 NPS -> 同机 NPC -> 127.0.0.1:4123
管理员 -> NPS 自己的 Web 管理面板
~~~

1. 在自己的服务器独立安装 NPS，在运行 CodexAPP 的电脑独立安装 NPC，按所选发行版的官方说明配置，客户端与服务端版本保持兼容。不在服务器安装 CodexAPP 或复制电脑 Codex 凭据。
2. 在 NPS 面板为这台电脑创建独立客户端身份，使用独立 vkey，按官方说明启动其 NPC。密钥和配置放在用户私有目录，不放入 CodexAPP 配置，不提交 Git、不公开到日志或截图。
3. 为该客户端创建 TCP 映射：服务器端口例如 18123，目标填写 127.0.0.1:4123。这里的目标由那台电脑的 NPC 访问，不是服务器自己的 4123。服务器管理端口、NPC 接入端口和应用映射端口必须分开，并核对现有占用。
4. 按需放行服务器安全组和防火墙；不要开放电脑的 4123 到公网，不覆盖未知服务、宝塔网站或已有规则。NPS 管理员密码不得使用发行包示例值，面板尽量限制来源访问。
5. 从另一网络访问 http://服务器IP:18123/health，再打开对应网页，选择“中继直连”，填写这台电脑原有的 CodexAPP 应用 Token。

NPS vkey、面板管理员密码和 CodexAPP 应用 Token 是不同凭据，不能互换。若由 NPC 配置文件注册隧道，按官方说明检查文件接入权限；不要把面板配置和文件配置同时重复注册同一端口。

这里说明外部映射的字段对应，不将 NPS 整合到业务或本地启动链路。可选的 NPC 安装快捷命令不生成连接配置、不自动运行 NPC。NPS/NPC 的 TLS 接入、日志、后台运行和面板防暴力破解由所选版本官方文档与管理员维护，项目不替用户生成或验证其配置。

### 两台电脑共享服务器

| 电脑 | 各自本地目标 | 服务器入口示例 | NPC 身份 |
|---|---|---|---|
| A | 127.0.0.1:4123 | 服务器IP:18123 | A 独立 vkey |
| B | 127.0.0.1:4123 | 服务器IP:18124 | B 独立 vkey |

两台电脑的本地端口可以相同，公网端口和客户端身份必须独立。不要共享同一个 vkey 或把独立 Codex 电脑配置成轮询负载均衡。访问 A 的入口使用 A 的应用 Token，B 同理。

## 5. 其他独立路线

- 无自有服务器：[README 的 Tailscale Serve 操作](../README.md)。只需用户自行维护 Tailscale，不要求使用 NPS。
- 已有 frp：由用户按照所选版本官方说明维护，项目内置部署和测试脚本已移除。
- 局域网：使用启动日志给出的电脑局域网地址和应用 Token，按需要放行来源受限的本机防火墙规则。

## 6. 安全和验收

公网 HTTP/WS 仅供临时联通测试，不执行真实任务或审批。即使 NPC 与 NPS 之间启用 TLS，浏览器到公网 HTTP 入口仍是明文；面板验证码、限频或登录载荷加密也不能代替 HTTPS。正式远程执行应由用户配置 HTTPS/WSS 或使用可信的私网加密入口。

先确认本机 /health，再确认映射入口 /health；WebSocket 还需单独确认 /ws 返回 101。健康检查成功不等于会话历史、审批和任务停止已通过公网验收。不得为测试自动发送提示词、自动审批或停止用户现有任务。

此前 NPS 整合的下载与隔离验证属于历史资料，不是当前内置功能保证。如本机仍有留存包、配置或报告，用户自行维护且不提交秘密；新的可选安装入口只安装 NPC 文件，不恢复旧整合工具。

官方项目：`https://github.com/djylb/nps`。请用户依据选定版本自行部署，不跟随未经验证的配置示例。
