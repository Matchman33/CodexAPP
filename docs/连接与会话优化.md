# 连接与会话优化

本次覆盖同设备重连、登录授权撤销、直连与云端共享核心，以及多客户端历史刷新合并。

## 同设备重连

新版 Agent 在配置目录保存 `agent.identity.json`，用于设备身份签名，与消息加密的 `agent.keys.json` 分开。Broker 每次登录生成一次性挑战；Agent 用设备私钥签名，Broker 校验成功后才允许同账号、同设备签名公钥、同消息加密公钥的新连接替换旧连接。旧连接停止路由，其迟到的关闭事件不会清理新连接。

另一台设备仍返回 `agent_already_online`，不自动抢占。设备身份文件缺失或主动换机时，需要先退出旧 Agent。旧 Agent 不提供签名身份，继续保留一账号一 Agent 的拒绝规则；首次升级应正常退出旧程序后再启动。

重连计时器绑定当前登录尝试；退出账号或切换账号后，旧的登录请求、连接事件和重试不能恢复已退出的会话。

## 免费账号与登录撤销

SQLite 自动增加 `accounts.auth_version`，令牌包含该版本。旧令牌在版本尚为 0 时保持兼容。修改密码或管理后台点击“退出全部设备”会递增版本，并断开该账号全部云连接；旧令牌不能重新建立连接。

云账号连接已取消会员机制，未停用且通过邮箱验证的账号可免费使用。管理员停用账号时立即断开云连接，并拒绝新的密码登录、设备认证和旧令牌连接。恢复账号后允许重新登录，但不会重新启用旧令牌。修改密码和验证邮箱都不会解除停用。

每次转发前再次检查发送者令牌和停用状态，心跳也会检查空闲连接，因此自然过期的登录令牌最迟约 30 秒被清理。数据库自动增加 `disabled` 字段；旧会员期限和兑换记录保留但不再参与授权。

新版 Agent 保存登录令牌以供断线恢复；收到登录撤销后清除令牌、记住需要手动登录的状态，不再直接用已保存密码悄悄重连。持有有效账号密码的用户仍可主动重新登录，退出登录不是禁用账号。

撤销的是云端访问权限，不终止本机任务、不自动批准审批，也不影响仍有有效本地 Token 的直连访问。终端会释放被撤销云连接的输入权，但不会自行结束进程。停用账号不会让直连失效。

## 共享本机核心

```text
直连网页 ── Token /ws ──┐
                       本机中继 → 一个 SessionHub → 一个 Codex app-server
云端手机 → Broker → Agent ── 本机 Token /ws ──┘
```

`npm start` 启动共享中继；`npm run start:agent` 启动云端连接及电脑面板。Agent 先连接本机中继，只有端口确实未监听时才尝试启动本机中继，并先占用端口再启动 Codex，避免并发启动两个控制进程。端口被无关服务占用、Token 不匹配或中继版本过旧时明确报错，不改用另一个端口启动第二套会话核心。重复运行 `npm start` 会检查 Token 和协议版本，匹配时提示使用现有中继。

源码运行时，Agent 默认使用或创建项目的 `codexapp.config.json`；打包程序找不到源码项目时，使用 Agent 配置目录下的 `relay.config.json`。可以在 Agent 配置中指定绝对路径 `relayConfigPath`，或通过环境变量 `CODEXAPP_RELAY_CONFIG` 让两个入口使用同一个配置文件。Agent 首次生成独立中继配置时，可用 `relayPort` 指定端口，默认 4123。

模型、沙箱、审批策略以共享中继配置为准，保存设置也由该中继负责。Agent 配置不再单独控制一份模型会话。已有中继的数据目录继续沿用；独立 Agent 启动的中继默认沿用配置目录中的 `sessions/`。历史文件不会迁移或删除。合并两个此前分别运行的服务时，应先等任务结束、处理队列，再选择要继续使用的中继配置与数据目录；两份旧进程的内存任务不能热合并。

两个入口保留原有消息协议。Agent 给每个已授权手机建立独立的本机连接，转发定向回复、流式内容、审批和终端事件。云端退出或 Broker 断开只释放云连接；共享核心中的任务继续执行。若本机中继重启，Agent 自动重连并发送新快照，不自动重放已发送的命令或终端按键。

“重启本项目”由共享中继处理：等待所有任务空闲、保存队列，存在活动终端时拒绝重启。由 `npm start` 持有中继时只重启中继；由 Agent 持有中继时重启 Agent 进程及其内置中继。直接通过 Node 启动仍遵循原来的受管启动限制。

SEA、Node 包和 Electron 的构建现在同时携带 `web/` 本地资源；分发时要连同网页目录、终端 worker 和原生依赖一起复制。已安装的旧二进制需要重新构建。

## 多客户端历史刷新

同一会话的并发 `watchThread` 请求共用一次读取；成功结果缓存 2 秒。每个客户端仍收到自己的 `requestId` 和 `clientId`，保持当前分页及滚动逻辑兼容。缓存只用于只读历史刷新，不用于审批、发送、停止或终端输入。

读取失败立即丢弃缓存。接续、发送、释放、状态通知或控制连接变化会使旧缓存失效；进行中的旧读取即使晚到，也不能覆盖已经进入运行状态的会话。不同会话的读取彼此独立。

## 升级顺序与验证

先备份并更新 Broker（包含 `deviceIdentity.mjs` 和数据库迁移），再在本机任务空闲后更新共享中继和 Agent。升级到共享核心前，应结束旧版重复运行的 Agent 控制进程，再启动新版；保留原有配对密钥、Token 和配置目录。
